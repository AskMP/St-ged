## Project Overview

**Name**: Stàged
**Description**: Free, offline-first PWA for household meal coordination. Replaces meal kit subscriptions with recipe discovery, collaborative meal planning, and one-tap Instacart fulfillment. "Digital pre-portioning" — buy exactly what you need, packaging-free.
**Language(s)**: TypeScript
**Framework(s)**: Turborepo monorepo — Vite+React PWA (web) + Hono (api) + Socket.io (real-time)

## Coding Conventions

- camelCase for variables and functions; PascalCase for React components and TypeScript types/interfaces; kebab-case for file names
- Barrel exports (`index.ts`) in each `src/` subdirectory -- import from the barrel, not deep paths (e.g., `import { Recipe } from '@staged/types'` not `'@staged/types/src/recipe'`)
- Absolute imports within each app via `@/` alias configured in `tsconfig.json` and `vite.config.ts`
- All types shared between `apps/web` and `apps/api` live in `packages/types/src/` -- never duplicate type definitions across packages
- Drizzle schema (`packages/db/src/schema/`) is the single source of truth for database shape; never write raw SQL outside migration files
- No business logic in route handlers -- routes call services; services contain all logic; Hono handlers orchestrate only
- All async route handlers use try/catch; use Hono's `HTTPException` for HTTP error responses
- Environment variables accessed only via `src/lib/env.ts` in each app (typed, validated with Zod at startup -- fail fast if required vars missing)
- No `any` types -- use `unknown` and type-narrow, or add the type to `packages/types/src/`
- Socket.io events use a typed `ServerToClientEvents` / `ClientToServerEvents` map defined in `packages/types/src/events.ts`
- Offline mutations: always write to Dexie first (optimistic UI), then queue in `SyncQueue` table, then flush on reconnect

## Testing

- **Test runner**: Vitest (unit + integration), Playwright (E2E)
- **Unit test location**: `tests/unit/` within each app; co-located `*.test.ts` alongside complex utilities
- **E2E test location**: `apps/web/tests/e2e/`
- **Run command**: `pnpm test` (all workspaces); `pnpm --filter web test`; `pnpm --filter api test`
- **E2E command**: `pnpm --filter web test:e2e`
- **Type check**: `pnpm type-check` (runs `tsc --noEmit` across all packages -- tests passing does NOT guarantee type safety)
- **Coverage target**: 75%

## Build & Run

```bash

# Run all dev servers in parallel (web on :5173, api on :3000)

# Run web app only
pnpm --filter web dev

# Run API only
pnpm --filter api dev

# Build all apps for production
pnpm build

# Run all tests
pnpm test

# Type check all packages
pnpm type-check

# Run E2E tests
pnpm --filter web test:e2e

# Database migrations
pnpm --filter @staged/db migrate

# Generate Drizzle migration from schema changes
pnpm --filter @staged/db generate
```

- Use ASCII punctuation in code, comments, and documentation -- no smart quotes, em-dashes, or curly apostrophes
- **Agent identity**: State your role and confidence level (High/Medium/Low) when providing recommendations
- **Review labels**: Use `[block]`, `[warn]`, `[nit]`, `[question]` on all code review feedback
- **File size**: Keep source files under 400 lines. The `check-loc-threshold.sh` hook warns automatically.
- **PR size**: Keep PRs under 150 net lines. Split larger changes into focused PRs.
- **Domain purity**: No cross-layer imports. UI must not import server modules. Config from env only.

## Project-Specific Rules

- **Railway deployment is post-MVP**: Do not attempt Railway deploys during development. All verification happens against `localhost:3000` (API) and `localhost:5173` (web). Railway deployment is gated on `01-verify-runtime` completing successfully -- the config files exist but are not to be used until then.
- **Offline-first is non-negotiable**: Any feature that fails when Chrome DevTools Network is set to "Offline" is a blocker. Test offline mode before marking any feature complete.
- **A2HS is a functional requirement**: The Add-to-Home-Screen prompt is NOT optional UX polish. iOS evicts non-installed PWA cache after 7 days. Prompt must appear in onboarding with clear benefit framing: "Add to Home Screen to keep your recipes available offline -- even without signal."
- **No Background Sync API**: Not supported on iOS. All offline sync uses the foreground-flush pattern: optimistic local write -> IndexedDB SyncQueue entry -> flush on `online` event or `visibilitychange`. Never architect around Background Sync.
- **Instacart IDP only**: The consumer developer program is the Instacart Developer Platform (IDP). Never reference "Instacart Connect" (retailer-only enterprise API). Affiliate enrollment via Impact.com. Commission: 5% of cart value within 7-day attribution window.
- **USDA FDC is self-hosted**: Never call the USDA FoodData Central API at runtime. Dataset is downloaded to `packages/usda/src/data/` (gitignored). Nutrition computed once at recipe-save time via Claude Haiku (LLM-as-parser) + local DB query; cached in `recipe.nutrition_per_serving` JSONB. Never re-call on recipe view.
- **No Spoonacular as primary**: 1-hour cache limit is incompatible with offline-first. Edamam used only for user-submitted recipe analysis (pay per new recipe, not per view).
- **Amazon Fresh excluded**: No public API exists. Any PR adding Amazon Fresh integration will be rejected.
- **Screen Wake Lock required in cooking view**: Step-by-step cooking view must request `navigator.wakeLock.request('screen')` to prevent screen timeout during cooking.
- **DMCA agent prerequisite**: Register DMCA designated agent at copyright.gov/dmca-agent/ before recipe URL import ships. Recipe import must fetch schema.org/Recipe JSON-LD structured data only -- never full-article HTML.
- **Eco claim precision**: Stàged's eco positioning is "digital pre-portioning eliminates packaging while preserving food-waste-reduction benefit." Never claim "we're greener than meal kits overall" -- U Michigan LCA (2019) shows meal kits have lower total CO2. The correct claim is packaging elimination, not total CO2.
